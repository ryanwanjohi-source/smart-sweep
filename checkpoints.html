The Four Checkpoints in Creating Smart Sweep

CHECKPOINTWHAT WAS DONETOOLS USEDWHAT IT PRODUCEDSTATUS
1. Design The requirements were listed first (the IPOS requirements table). Then the system was drawn: use case diagram, class diagram, sequence diagram, ERD and database schema, plus the six wireframes for the screens. draw.io (diagrams.net), Figma The full diagram set and the wireframes — also Figures 4.1 to 4.12 in Chapter 4 of the proposal Complete
2. Website The screens from the wireframes were built as web pages in HTML, with one stylesheet in CSS giving them their colours and layout. The code is kept simple, with comments, and uses no JavaScript. VS Code, Live Server The 10 pages of this system (login, dashboard, about, bins, alerts, routes, checkpoints, reports, users) and css/style.css Complete
3. Database The database was designed from the ERD and schema of Checkpoint 1, then created with SQL: the smart_sweep database, its 15 tables with their keys and foreign keys, and the demo data loaded in. SQL — smart_sweep.sql smart_sweep.sql (the creation script) and smart_sweep.db (the created database: 15 tables, 86 records) Complete
4. Testing Every page was validated (tags, links and styles). Every diagram was opened and verified in the draw.io editor. Queries were run on the database and checked against what the website shows. VS Code, draw.io editor, SQL queries A checked system, ready to present: log in, read the dashboard, answer an alert, follow a route, and finish at the reports Checks done — presentation remains

The checkpoints are passed in order: the design (1) guides the website (2) and the database (3), and testing (4) checks both against the design.
